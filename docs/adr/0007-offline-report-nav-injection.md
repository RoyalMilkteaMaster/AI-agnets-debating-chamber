# 0007 離線報告五導覽採伺服器回應注入

## 背景

2026-08-10 核准需求要求五導覽（即時辯論／歷史與命中率／市場報告／完整辯論／設定）在所有頁面常駐，包含離線產出的 `report.html` 與 `debate.html`。但這兩個檔案受兩條既有契約約束：run artifact 唯讀（檔案產出後不得修改），以及離線 bundle 自足契約（檔案直接開啟或分享給別人時必須自己能看，站內連結在無伺服器情境是死連結——先前正因此刻意移除過指回伺服器的分頁）。

## 決策

五導覽不寫進檔案。`server.py` 在回應 run artifact 中 `report.html`／`debate.html` 的 text/html 請求時，於 `<body>` 標籤後插入純 HTML 導覽列（零 script，樣式走站內樣式表 route）；找不到插入點時原樣送出。磁碟檔案一字不動。

## 理由

曾在三個方案間取捨：

1. **回應時注入（採納）**：檔案不動、舊 run 同樣受惠、分享檔永無死連結；頁面一體、列印與捲動自然。
2. 檔案內建五導覽：分享出去或伺服器沒開時三個站內連結是死的；舊 run 唯讀不可回溯，新舊 run 行為分裂。
3. iframe 包框頁：原頁一像素不變，但雙層捲動、列印迷惑、體感笨重。

## 主要後果

- 「經伺服器瀏覽」與「直接開檔」看到的導覽不同（五導覽 vs 自足兩分頁），此為刻意設計。
- 注入器成為 artifact 回應路徑上的新環節，需測試插入與略過（無插入點）兩條路徑。
- 舊 run 紙白風頁面上會出現一條新設計風導覽列，兩種風格同框，已核准接受。
