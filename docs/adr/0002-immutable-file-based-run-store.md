# ADR 0002：不可變的檔案式 Run Store

- 狀態：Accepted
- 日期：2026-08-01

## 背景

七個研究席會並行產生證據、立場與辯論。產品需要保存原文、網址、時間、模型、替補與票數，並證明 Core 沒有改寫少數意見。五分鐘研究產生的資料量有限，使用資料庫、向量 RAG 或 FinGPT 會增加環境、啟動與失敗風險。

## 決策

- 每個 Run 使用 Data Root 下的唯一 `run_id` 目錄。
- 每個 Research seat／Attempt 只寫自己的隔離目錄。
- Python 單一寫入者驗證後合併成 `evidence.jsonl`、`debate.jsonl` 與票數紀錄。
- `T+5:00` 產生不可修改的 Evidence snapshot；更正使用追加紀錄，不覆寫原證據。
- 報告、共享快照與 Agent 發言保存來源識別及內容雜湊。
- MVP 不使用資料庫、向量 RAG 或 FinGPT；所有七席讀取完整、受控大小的證據卡集合。
- 執行歷史不自動覆蓋或刪除。

## 理由

- 單一寫入者避免七席同時寫入造成交錯、覆蓋與歸屬不明。
- JSON／JSONL 可直接檢查、diff、雜湊與交付，不需要額外服務。
- 小型證據集合全部共享，比向量檢索更不容易漏掉反證。
- 每次執行都是自包含稽核包，適合黑客松展示與追查。

## 主要後果

- Schema 必須版本化，格式錯誤需修正或由非投票 Format Repair Agent 整理。
- Run 數量增加會占用磁碟，但 MVP 不自動清除；刪除必須由使用者指定 run ID。
- 若未來證據量實測超出模型上下文，需另立決策評估索引或 RAG，不能直接改變本 ADR。
