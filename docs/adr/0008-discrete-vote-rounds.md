# 0008 離散四輪投票制、提示詞層證據閘門與挑戰機制退役

- 日期：2026-08-10
- 狀態：已核准

## 背景

比賽版辯論採「連續門檻階梯」：封存後開場盲投（7/7 直過），之後持續辯論，共識門檻隨時間遞減（6→T+8:00 後 5→T+10:00 強停 4），且每席必須完成一輪被指派的反方挑戰，票才算有效。使用者實際期望的流程是「離散投票輪」：固定時刻開票、逐輪降低門檻，且第一輪開票前各席只能依自己蒐集的證據獨立判斷，未達共識才交換資料、以證據互相說服。兩者在狀態機結構、證據可見性與有效票定義上都不同，無法靠改設定值銜接。

## 決策

1. **輪陣列取代具名階梯**：`config/debate_rules.json` 升 `schema_version: 2`，以 `vote_rounds: [{open_offset_ms, threshold}]`（60s/7、150s/6、240s/5、330s/4）＋ `final_settle_offset_ms`（360s）表達時間表；全部 offset 錨定該 run 的證據封存時刻（單幣 4:00、比較題 4:30，字面時刻表即單幣題）。輪數由陣列長度決定，消費端（狀態機、驗證器、直播頁、設定頁）一律迴圈推導，不寫死。
2. **盲投直過併入第一輪**：七席開場票全到且同立場即提前開票結案，不必等牆；否則第一輪在封存+60s 開票。
3. **提示詞層證據閘門**：封存快照檔案照舊產生；第一輪開票前，各席提示詞只注入自席 `seat_id` 的證據卡；第一輪未過後恢復完整快照注入（＝資料交換）。不新增任何 run artifact。
4. **反方挑戰正式關卡退役**：挑戰配對與魔鬼代言人輪替移除；輪間改為自由辯論 turn（提示詞語意：用證據說服對方、不盲從也不死守）；有效票＝開票當下各席最新公開立場。
5. **舊 run 相容**：manifest 規則快照機制沿用，`contract_validator` 保留 v1 讀取分支；`run_verifier` 以該 run 當時的規則驗證，合法 stop_reason 由規則快照推導而非寫死枚舉。

## 理由

- 「輪」本來就是使用者心智模型中的一級概念；把它做成資料，狀態機與驗證器的 if/elif 特例全部消失（資料結構消特例）。
- 封存錨定讓「比較題 +30 秒」這條已被實測證明必要的規則（2026-08-02）自然成立，不需要第二套時間表。
- 提示詞層閘門與實體分席快照效果相同（agent 唯一資訊入口是提示詞），但不動已凍結的 run 檔案契約，改動面最小。
- 資料交換＋重新判斷＋自由辯論在功能上取代指派式挑戰：每席在改票前都已讀過對方證據，對抗性由流程保證而非配對機制。

## 主要後果

- `debate_rules.py`、`debate_state_machine.py`、`debate_driver.py`、`contract_validator.py`、`run_verifier.py`、`webapp/live.py`、`webapp/settings.py` 七處同步改版；`prompt_builder` 的「七席共用區塊逐位元相同」契約弱化為「同階段內相同」。
- 失去「每席一定被指派挑戰過一次」的強制保證，對抗性依賴資料交換後的自由辯論品質。
- 設定頁需要新增 v2 鍵的中文標籤；v1 設定檔會被 fail-closed 拒絕，屬一次性手動遷移。
