# ADR 0003：燈號改純票數五級制（藍綠黃橘紅）＋兩條降級與輿情席豁免

- 日期：2026-08-05
- 狀態：已核准

## 背景

比賽版信心燈號為 red/orange/yellow/yellow_green/green 五級，票數只是上限，之後由證據品質規則（獨立網域數、證據類別數 elif 級聯、30 天時效、低可信來源、致命反證、矛盾）多層降級。`report_contract.py` 的類別數 elif 級聯存在順序缺陷：7 票且類別充足時會誤入 6 票層級的檢查被降到 yellow，且無測試鎖定該組合。使用者多次觀察到「票數與燈號對不上」。

## 決策

1. 燈號＝最終採納立場的有效票數：7 藍（blue，新增級）／6 綠／5 黃／4 橘／<4 紅。
2. 僅保留兩條降級：①引用來源少於 2 個獨立網域→降一級；②引用含低可信（非 tier 1/2）來源→降一級，但輿情席（social-macro）的證據豁免。
3. 移除類別數 elif 級聯（bug 隨之消滅）、30 天時效降級與其餘品質規則。
4. `confidence_cap`、`_validate_confidence`、`confidence_ceiling` 撰稿提示、renderer 樣式、`run_verifier` 五處同步，規則寫入 `config/debate_rules.json` 單一來源。

## 理由

- 使用者要求燈號直接反映共識強度，規則透明可預測；證據品質把關交給七席同儕辯論（與移除禁詞審查同一治理哲學）。
- 保留兩條最小降級是使用者明確要求：「來源不那麼可信可以降級」，防單一來源綁架共識。
- 輿情席職責即蒐集三手輿情訊號，對其套用來源等級降級屬於誤殺。

## 主要後果

- 「7 票但證據類別單一」也能拿藍燈——共識強度與證據廣度自此脫鉤，讀報告時須自行看證據區。
- 燈號語意變更後，與舊 run 的燈號不可直接比較（舊 run 已全數刪除，無實際影響）。
- yellow_green 級退場，renderer 與報告 schema 移除該值。
