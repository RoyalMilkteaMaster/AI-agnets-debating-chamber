5. 已知風險與回復方式

  • _follow 每趟組裝 payload:換取「走到哪一關」單一計算點;實測 0.022ms/次,本機單人可忽略。
  • 封存前每 0.5 秒一次 is_file() 檢查:量級與既有 run_finished 相同;封存後旗標關閉不再讀。
  • 大 run 的封存幀較大(37 卡實例):每 stream 僅一次;本機 SSE 無交付風險。
  • evidence_view 單一權威:未來改補字規則會同時影響 run 詳情頁與即時房間——這正是設計意圖,修改時需知悉。
  • focus 欄位含 client 未用的 confidence_level:刻意不裁切,避免第二種形狀。
  • 回復方式:全部變更未 commit,集中於 8 個檔案;如需還原,可先以 git diff > backup.patch 留底再捨棄工作樹修改。各站 diff 備份已存於本次 session scratchpad(ticket01-snapshot.diff、ticket02-snapshot-v2.diff、ticket03-snapshot.diff)。
  • 環境備註:全套測試在 /mnt/d(DrvFs)上約需 10 分鐘,為既有現象;與本次變更無關。
