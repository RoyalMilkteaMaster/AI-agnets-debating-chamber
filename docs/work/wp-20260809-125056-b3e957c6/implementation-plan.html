修改前

  • 預設 both 模式：Reviewer A 只執行 Spec Review（是否符合已核准需求與驗收條件），Reviewer B 只執行 Standards Review（能跑、可讀、架構清楚、無明顯衍生問題）。
  • 單 Reviewer 模式（a_only 或 b_only）才由該位覆蓋兩軸，避免重複審查。
  • 實際名單由執行 Task 最新的 reviewers 設定決定，Ticket 不自行固定或搜尋設定。
  • 每位啟用的 Reviewer 都載入程式碼審查技能，只執行 Coordinator 指定的審查軸。

Findings 處理與定向複驗

  • 每個 Finding 由提出它的原 Reviewer 擁有。
  • Developer 不得照單全收，必須重現、查證或以測試驗證；建議不正確時要提出證據並維持立場。
  • Developer 修正或反駁後，只交回該 Finding 的原 Reviewer 定向複驗；Coordinator 不重排嚴重度、不合併成裁決、不用另一個模型投票。
  • Finding Owner 必須依證據關閉、降級或撤回。未達共識前 Ticket 不得標記完成。
  • 只有缺少產品價值、公開契約、不可逆資料處置或安全接受程度等關鍵決策時，才交給使用者。
