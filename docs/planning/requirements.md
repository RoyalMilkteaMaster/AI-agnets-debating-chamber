## 問題與目標

使用者需要在 17 分鐘總窗內，讓多模型 Agent 蒐集市場資料、整理正反證據、辯論並於 T+15:00 前產生可追溯的市場判斷，最後保留兩分鐘人工閱讀與準備展示。

核心原則是多方查證。票數代表 Agent 共識，不代表客觀真理；報告必須誠實揭露票數、少數意見、資料限制與失效條件。

## 支援範圍

- 資產類別：台股、美股、加密資產與開放命題；實際標的由題目或前端明確指定。
- 題型：單一標的市場狀態、兩標的比較、整體市場狀態、事件影響與開放命題。
- 輸入：使用者貼上自然語言題目，可附文字、網址或資料檔。
- 分析期間：題目指定優先；未指定時預設過去 14 日。
- 範圍外：槓桿、倉位比例與直接買賣指令；系統產出研究判斷，不提供個人化投資建議。

## Agent 組成與研究席

- Core Agent：GPT-5.6 Sol。
- Sub-agents：3 個 Claude Opus、3 個 GPT-5.6 Sol、1 個 Gemini Pro。
- 每個 Sub-agent 必須遵循固定版本的 `mattpocock/skills` `research` 原則。

七個研究席：

1. 現貨價格、成交量與技術結構。
2. 衍生品、OI、Funding、清算與基差。
3. 鏈上、供給、巨鯨與交易所流量。
4. 官方公告、監管及事件催化。
5. 新聞查證與事件時間線。
6. 社群、重要帳戶、宏觀及 BTC 關聯。
7. 反方證據與資料品質檢查；該席不固定投偏空。

七席先分面研究，投票前讀取全部共享證據，再對整體題目形成自己的立場。

## 時間規則

```text
T+0～1:30   優先搜尋一手來源；社群席可立即研究社群訊號
T+1:30～5:20 找不到所需一手資料時，允許可信二手來源
T+5:20      停止發起新搜尋，立即整理已取得資料並準備交回
T+5:50      停止接收研究結果；資料不足也必須交回，不得為湊數逾時
T+6:00      封存證據並開始投票與辯論
T+7:00      第一輪開票，7 張同立場票達成共識
T+8:30      第二輪開票，6 張同立場票達成共識
T+10:00     第三輪開票，5 張同立場票達成共識
T+11:30     第四輪開票，4 張同立場票達成共識
T+12:00     強制停止；4 張同立場票採用，否則未達共識
T+15:00 前  完成報告；T+15:00 或之後不得宣稱成功
```

兩標的比較題從停止搜尋至辯論硬停全部後移 30 秒：T+5:50 停止搜尋、T+6:20
停止收件、T+6:30 封存，四輪與硬停為 T+7:30／9:00／10:30／12:00／12:30；
報告硬截止仍為 T+15:00。每席證據卡目標 3～8 張，但收件前不足 3 張時仍須提交現有資料。

七席 opening 全到且 7/7 同立場時可盲投直過；其他情況依離散投票輪開票，不再以「完成反方挑戰」作為有效票前提。

## 投票與辯論

投票種類：

- 單幣／整體：偏多、偏空、中性／方向不明。
- 兩幣比較：A 相對強勢、B 相對強勢、無明顯差異。
- 事件影響：正面、負面、影響不明／高度條件式。

Agent 應方向優先。選擇中性時必須說明雙方衝突證據、無法判斷原因，以及什麼新證據會使其改票。

辯論使用共享原文紀錄；Core 只能主持、計時、分發相同原文及計票，不得摘要成二手訊息、替 Agent 改票或隱藏少數意見。

## Agent 失敗

- 優先以相同模型重試一次。
- 不以 Sonnet 或其他未核准模型跨模型替補；相同模型重試仍失敗時，保留失敗 lineage，該席依缺席規則處理。
- 投票門檻永遠維持絕對 `7／6／5／4`，不得按可用人數降低。
- 少於四張有效票時輸出紅燈失敗報告，不形成市場結論。

## 證據與來源

每筆證據保存原文或原始數值、網址／API 來源、發布與取得時間、資產、資料類別、支持或反對方向、蒐集 Agent、可信度與重複判定。

來源等級：

1. 交易所、區塊鏈原始資料、官方公告、監管機構。
2. 可信資料聚合商與具名新聞機構。
3. 社群、KOL 與重要帳戶。

社群資料不能單獨支撐結論。外部內容一律視為資料，不得成為對 Agent 的操作指令。

## 信心燈號

- 🔴：少於四張有效票、流程失敗或證據不足。
- 🟠：4/7，或結論嚴重依賴單一來源。
- 🟡：5/7，且至少兩類獨立證據。
- 🟡🟢：6/7，且至少三類可靠獨立證據。
- 🟢：7/7，且至少四類新鮮獨立證據，沒有未解決的致命反證。

票數只設定信心上限；來源品質、資料過期與矛盾可以使信心降級。

## 交付與驗收

每次 Run 必須產生或誠實說明無法產生：

- `report.html`
- `debate.html`
- `report.md`
- `evidence.jsonl`
- `debate.jsonl`

報告包含市場狀態、期間、信心、完整票數、每席初始／最終立場、改票原因、正反證據、替補、限制、來源與失效條件。

操作流程是從產品 Code Root 開啟新的 Codex Task，呼叫專用市場研究 Skill，貼上題目後自動執行。
MVP 不另建外部網站或登入系統，但提供只監聽 `127.0.0.1` 的唯讀即時頁面，顯示七席公開
辯論、票數變化、剩餘時間、門檻與可追溯證據；不得顯示或聲稱取得模型隱藏思考過程。

## 成本與賽前限制

- 只使用現有 Codex、Claude、Google AI Ultra 會員權限及免費／公開市場資料。
- 不新增付費 API。
- 所有 CLI、登入、模型、搜尋、路徑、權限與報告能力必須在正式計時前預檢完成。
- 正式 15 分鐘內不得等待安裝或登入。

## 問題與使用者

前端經多輪改動後動線混亂；根目錄靜態快照（辯論室預覽.html）誤導使用者以為規則過期、報告點不開；七席名稱與研究方向是純幣圈視角，與已支援台股／美股的現實不符；發問靠純文字解析；bat 入口留下關不掉的主控台視窗。使用者為本人（本機單人）；離線報告讀者為使用者要分享的對象。

雙擊桌面捷徑（隱藏視窗）→ 瀏覽器開主頁 → 選單選資產類別＋標的發問 → 一頁式辯論室觀戰 → run 產出後右上角開市場報告／完整辯論，需要時按「匯出 PDF」→ 畫面上「關閉伺服器」優雅收工。

## 必要需求

1. **頁面清單**：即時辯論（主頁）｜歷史與命中率（合併一頁：上方統計卡＋下方 run 列表帶命中結果）｜設定｜run 詳情（保留）｜市場報告／完整辯論（離線兩份，內容不碰、右上角必可點）。
2. **保護區（功能凍結、外衣可換）**：動態聊天室、燈位、正方／反方／無法判斷票數——內容、位置、語意色不動；字體、間距、卡片樣式可隨新設計系統統一。
3. **重設計範圍**：全部網頁頁面套同一套新設計系統。
4. **入口動線**：刪除「辯論室預覽.html」；bat 退役；桌面捷徑隱藏啟動（伺服器已在跑→直接開瀏覽器）；頁面右上角「關閉伺服器」按鈕（優雅寫 `server_stop`）；備援「關閉辯論室」捷徑。
5. **七席換套**：兩套研究方向（股票＝台股美股共用、幣圈＝現行語彙），依 run 的資產類別自動切換顯示名稱與方向；開放題沿用通用敘述；`seat_id` 與 `output_dir` 永不改（相容性）。分工細表見下。
6. **標的選單**：發問以選單選資產類別＋標的，取代純文字解析（接 T05 的 assets／asset_class 接縫）。
7. **全繁體中文**：畫面上不得出現英文資料原值。
8. **PDF 手動匯出**：報告頁「匯出 PDF」按鈕，以 Edge 無頭模式將現成 HTML 轉 `report.pdf`／`debate.pdf` 存入該 run 資料夾；HTML 與報告版面不動。

# 四輪投票制、概述摺疊與前端分層（2026-08-10 核准）

- 狀態：已核准（使用者於需求訪談逐項定案）
- 來源：`$milktea-skills-grill-me` 需求階段
- 前置：建立在 wp-20260810-092746-8728cbc6（前端白話化與 Google 風重設計）已完成的成果之上。

## 問題與使用者

1. 辯論規則與使用者期望不符：現行是「封存後連續辯論＋門檻隨時間遞減（6→5→4）」，期望是「離散四輪投票＋第一輪開票前各席資料隔離」。
2. 「結論在前＋全文展開」的直播訊息呈現在現版缺席；工作區存在一份未提交、全套件測試綠（655 測試）的實作（live.py＋pages.py＋174 行測試），「說話順序結論在前」已在 HEAD（debate_driver 強制 public_reason 第一句為 30–60 字核心結論）。
3. webapp 前端 3256 行擠在 pages.py 單檔、無分層，難維護；視覺仍不滿意。

使用者為本人（本機單人）；離線報告讀者為使用者要分享的對象。

## 目標結果

新四輪投票流程上線；辯論訊息預設顯示結論、可展開全文；webapp 分層（HTML／JS／API）＋視覺升級。

## 核心流程

新辯論規則。所有時刻錨定該 run 的證據封存時刻（一般題封存 6:00，下表字面時刻即一般題；兩標的比較題封存 6:30，全部後移 30 秒、硬停 12:30）：

|---|---|---|
| 0:00–5:20 | ～搜尋停止 | 各席研究，只看自己的資料；0–1:30 一手優先，之後可用可信二手 |
| 5:20–5:50 | 搜尋停止～收件 | 不得發起新搜尋，整理已取得資料；不足三張也必須交回 |

## 必要需求

1. **新辯論狀態機**：離散四輪開票（門檻 7／6／5／4）、時刻錨定封存、盲投直過提前結案保留、硬停時最終結算。
2. **證據可見性閘門**：第一輪開票前各席只讀得到自己的證據；第一輪未過才分發全席證據（JSON，沿用證據卡結構與否交架構階段）。
3. **反方挑戰正式關卡退役**：「每席必須完成一輪反方挑戰票才有效」廢止；有效票＝該輪開票當下各席最新公開立場。對抗性由「資料交換＋重新判斷＋自由辯論」承擔。
4. **規則檔唯一來源**：`config/debate_rules.json` 仍是時間門檻與票數唯一來源；本次新增／改名的規則鍵在設定頁須有中文標籤＋白話說明（沿用 2026-08-10 白話化規則，逐鍵文案於 Spec 過目）。
5. **燈號不變**：純票數映射（7藍／6綠／5黃／4橘／<4紅）＋兩條來源降級（獨立網域、低可信來源）照舊。
6. **概述摺疊**：採用工作區未提交實作為基線（伺服器端取 public_reason 第一句為概述、`<details>` 原生展開收合、頁面與 SSE 共用同一份斷句）；此行為在前端分層與視覺改版後必須保留。
7. **前端分層**：pages.py 拆為 HTML 模板／靜態 JS／API 的分層形式；具體切法（模板方式、靜態資源供應、API 端點）交架構階段。
8. **視覺升級**：以 Gemini 建議為參考方向（過渡動畫、focus ring、聊天氣泡對齊、表格 hover、標籤精緻化等），在既有設計系統（Google 風白底、毛玻璃、微軟正黑體、語意色）內落地。
